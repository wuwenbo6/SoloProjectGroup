# 修复说明文档

## 已修复的问题

### 1. 离线编辑同步冲突问题 (CRDT 算法实现)

#### 问题原因
原始实现使用简单的操作队列方式，没有真正的 CRDT 算法来处理并发编辑冲突。当多个用户离线编辑同一文档后再同步时，会出现内容覆盖或丢失的问题。

#### 解决方案
**集成 Yjs CRDT 库** - 一个经过实战验证的 CRDT 实现：

**后端修改 (`backend/src/`):**
- `models/document.js`: 新增 `yjsState` 字段存储 CRDT 状态
- `socket/sync.js`: 
  - 使用 `Y.Doc` 管理文档状态
  - `Y.applyUpdate()` 应用更新操作
  - `Y.encodeStateAsUpdate()` 序列化状态
  - 实现离线变更同步接口 `sync-offline-changes`
  - 当无用户在线时自动保存状态到数据库

**前端修改 (`frontend/src/store/document.js`):**
- 使用 `Y.Doc` 和 `Y.Text` 管理共享文档状态
- `y-codemirror` 绑定 CodeMirror 编辑器实现协同编辑
- IndexedDB 存储本地 Yjs 状态和待同步更新
- 网络恢复时自动同步离线期间的所有更新
- 监听 Yjs `update` 事件实现实时协作

**CRDT 工作原理:**
- Yjs 使用基于操作的 OT（操作转换）和状态向量
- 每个客户端操作都有唯一的 Lamport 时间戳
- 并发操作自动合并，保证最终一致性
- 无需中央服务器协调，支持 P2P 同步

### 2. 图片粘贴上传问题

#### 问题原因
原始实现直接将图片作为 base64 编码字符串插入 Markdown，导致：
- 文档体积急剧增大
- 预览时可能显示断裂（如果 base64 过大或格式错误）
- 无法持久化存储

#### 解决方案
**实现图片上传服务 + URL 引用方式**

**后端修改 (`backend/src/index.js`):**
- 集成 `multer` 中间件处理文件上传
- 创建 `/api/upload` 接口接收图片文件
- 文件保存到 `uploads/` 目录，使用 UUID 重命名
- 返回可访问的 HTTP URL (http://localhost:3001/uploads/xxx.png)
- 限制文件类型（仅图片）和大小（10MB）
- 静态文件服务提供上传文件访问

**前端修改:**
- `store/document.js`: 新增 `uploadImage()` 和 `insertImageAtCursor()` 方法
- `components/Editor.vue`: 
  - 监听粘贴事件，检测剪贴板图片
  - 支持拖拽图片上传
  - 上传成功后插入 Markdown 图片语法 `![name](url)`
  - 错误处理和用户反馈

## 运行步骤

### 1. 启动数据库服务
```bash
cd md-editor
docker-compose up -d
```

### 2. 启动后端服务
```bash
cd backend
npm install
npm start
```
- 后端运行在 http://localhost:3001
- 图片上传接口: http://localhost:3001/api/upload
- 图片访问路径: http://localhost:3001/uploads/[filename]

### 3. 启动前端服务
```bash
cd frontend
npm install
npm run dev
```
- 前端运行在 http://localhost:3000

## 功能验证

### 离线同步测试
1. 打开两个浏览器窗口访问同一文档
2. 在两个窗口分别编辑不同内容
3. 断开网络（可使用浏览器开发者工具模拟）
4. 在两个窗口继续编辑（离线模式）
5. 恢复网络
6. 验证两个窗口内容正确合并，无内容丢失或覆盖

### 图片上传测试
1. 在编辑器中粘贴图片（Ctrl+V / Cmd+V）
2. 或拖拽图片文件到编辑器
3. 观察图片自动上传并显示 URL
4. 验证预览区域正确显示图片
5. 检查后端 `uploads/` 目录有对应文件

### 多人协作测试
1. 打开多个浏览器窗口
2. 所有窗口加入同一文档

4. 在任意窗口编辑，其他窗口实时同步
5. 验证光标位置和编辑操作正确同步
